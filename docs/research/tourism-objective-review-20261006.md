# ver2 수정 및 객관적 재검토 — 2026-10-06

검토 기준은 `a9b31c8`와 이 보고서와 함께 커밋되는 변경이다. `origin/main` 기준점은 `2feb2eb`이다. 제품·운영 가치와 코드 정확성을 분리해 평가했다. 특정 인물이나 다른 모델이 검토했다는 주장은 하지 않는다.

## 재현해서 수정한 문제

### P2: 검증되지 않은 세션 쿠키로 전역 API 한도 우회

`server/http/rate-limit.ts`는 64자리 hex 쿠키만 있으면 별도 세션 버킷을 만들었다. 공개 `/api/regions`에 매번 다른 가짜 쿠키를 보내면 새 버킷을 받아 IP 한도를 피했다. 유효기간이 지난 세션, 삭제된 세션, 정지 계정도 같은 문제가 있었다. `main`에 이미 있던 문제이며 관광 추천 인증 자체의 우회는 아니다. 사용자별 추천 POST 한도는 별도로 적용되고 있었다.

수정 전 실험은 실제 Express 앱과 PostgreSQL을 사용하고 전역 한도를 3회로 낮춰 실행했다. 네 번째 요청이 429여야 하는데 200이 나왔다. 최초 회귀 테스트 10개 중 8개가 실패했다.

이제 활성 사용자·유효한 세션을 DB에서 검증한 쿠키만 세션 버킷을 받는다. 나머지는 쿠키 없는 요청과 같은 IP 버킷을 공유한다. 검증된 세션끼리는 같은 NAT IP에서도 한도를 분리한다. IPv6의 기본 /56 집계는 유지한다. 인증 조회 결과는 같은 응답 객체 안에서만 공유해 보호된 API의 중복 조회를 피하고, 다음 요청에서는 만료·철회·정지 상태를 다시 확인한다. DB 장애는 검증 없이 허용하지 않고 503으로 처리한다.

최종 회귀 테스트 12개는 쿠키 회전, 익명 요청과의 한도 공유, 유효 세션 분리, IPv6, 다음 요청의 인증 무효화, 요청당 인증 조회 1회, 토큰·해시 응답 제외, DB 장애를 검증한다. 두 신규 테스트 파일 모두 `test:ci`에 포함했다.

### P2: 외부 경로의 잘못된 수치를 실제 이동정보로 수락

Google 경로의 `parseFloat`는 `60mins` 같은 문자열을 60초로 읽었고, 음수 거리·시간도 수락했다. Valhalla는 유한성만 확인해 음수 값과 km→m 변환 시 범위를 넘는 값까지 반환했다. 역시 `main`부터 있던 문제다.

이는 통제된 잘못된 provider 응답을 주입해 재현한 결과다. 실제 Google/Valhalla가 이런 응답을 보냈다는 뜻은 아니다. 기존 일정의 이동 비교 화면도 같은 함수를 사용하므로 관광 그래프의 `complete` 검사만으로는 모든 표시를 보호할 수 없었다.

Google 거리에는 음이 아닌 int32 정수, 시간에는 완전한 protobuf seconds 문자열과 최대 9자리 소수·값 범위를 요구한다. Valhalla는 음이 아닌 원본 값과 단위 변환 후 안전한 정수를 요구한다. 잘못된 응답은 직선거리와 `durationSeconds: null`로 처리한다. 0 거리·0 시간과 정상 소수 초는 허용한다. [Google Routes 명세](https://developers.google.com/maps/documentation/routes/reference/rest/v2/TopLevel/computeRoutes), [protobuf Duration](https://protobuf.dev/reference/protobuf/google.protobuf/#duration).

최종 테스트는 26개다. 일회용 복사본의 `a9b31c8` 코드에 동일한 최종 테스트를 적용하면 19개 실패·7개 통과하고, 수정 후에는 26개가 모두 통과한다. 실패 응답 뒤 정상 응답으로 복구되는 것도 검사한다. Google Routes는 기존 정책대로 완료 결과를 캐시하지 않으며, Valhalla만 정상 완료 결과를 재사용한다. 캐시 정책을 임의로 완화하지 않았다.

### 의존성 보안 패치

기존 허용 범위 안에서 잠금 파일만 갱신했다. 직접 의존성 추가나 강제 override는 없다.

- 운영: `ip-address` 10.7.0 → 10.7.3
- 개발: `brace-expansion` 1.1.18 → 1.1.21, 5.0.9 → 5.0.12

패치 전 전체 감사는 새 `brace-expansion` high 항목 1건을 보고했다. 패치 후 실제 npm 전체 감사와 운영 감사 래퍼는 모두 0건이다. 이 수치는 검사 시점의 공개 advisory 기준이며 앱에서 원격 공격이 가능했음을 입증한 결과는 아니다. 원본 작업 폴더의 설치본은 변경하지 않고 검증 worktree에 독립적으로 설치했다.

[ip-address 보안 공지](https://github.com/advisories/GHSA-j6r3-76f7-8jcv), [brace-expansion 보안 공지](https://github.com/advisories/GHSA-q2hr-2g5m-vwhr).

## 수정 후 코드 검토

검토 범위는 새 인증 검증·한도·provider 응답 처리와 기존 관광 핵심 경로다. 수집/정제 정책, 발행/철회/보존, 공통 시설 매칭, 검색/그래프, 프런트 추천·교체, CI 감사와 브라우저 검증을 다시 읽었다. 다음은 코드와 회귀 검사에서 확인한 사실이다.

| 경계 | 확인 내용 |
| --- | --- |
| 여행 접근 | 추천 라우트 전에 로그인과 소유자/수락 동행자 검사가 실행된다. 한도 키 검증 결과를 여행 권한으로 대신하지 않는다. |
| 일정 변경 | 추천 조회는 저장하지 않는다. 사용자 확정 PATCH는 기존 날짜 revision과 장소 목록을 검사한다. |
| 유지 장소 | 유지 순서를 보존하고 남는 수를 근거 순위로 먼저 고른 뒤 동선을 정렬한다. |
| 근거 | 추천이 인용하는 시설 자료만 응답에 포함한다. 행사와 반복·날짜 불명 참고 목록은 구분된다. |
| 발행 | 출처 승인·활성·정책·parser·resource 범위·fetch 시점을 검사한다. 더 오래된 fetch의 활성화와 불일치 재처리를 거절한다. |
| 철회 | stable ID 철회 표식이 새 발행에 상속된다. 검색은 snapshot의 철회 시각과 별도 철회 표식을 모두 확인한다. |
| 보존 | 기본 정리는 읽기 전용 미리보기다. 적용은 출처를 잠그고 활성·최신·최근 snapshot을 보호한다. |
| 별칭 | 원문/카탈로그 지문 불일치 시 적용하지 않고 진단한다. 실패한 별칭 로딩 Promise는 고정 캐시하지 않는다. |
| 외부 호출 | 시간 제한과 취소 신호를 전달한다. 자체 호스팅 Valhalla에는 프로세스별 동시성·대기열 상한이 이미 있다. |
| 캐시 | 취소 신호가 있는 요청은 진행 중 요청을 공유하지 않는다. 취소가 다른 사용자에게 전파되지 않는 기존 정책이다. |
| UI | 같은 조건의 조회 실패 후 코스 목록은 유지하며 확정 가능한 오래된 미리보기는 제거한다. 조건·여행·날짜 변경은 늦은 응답을 무효화한다. |
| CI 감사 | 실제 npm 10.9.9 CLI와 loopback 레지스트리로 오류 분류·재시도·실패 유지·시간 제한을 확인한다. |

수정 후 이 검토 범위에서 추가로 재현한 P1/P2 결함은 없다. 모든 코드의 무결함이나 운영 용량을 증명한 결론은 아니다.

## 제품·운영 관점

LangGraph `StateGraph`는 실제 코드로 구현되어 있으며 기본 생성은 규칙 기반이다. LLM이나 AWS 연결이 없다는 이유로 그래프 구현이 없는 것은 아니다. 현재 코드는 공개 자료와 후보를 검색하고, 예보·규칙·검증·재검색·경로 미리보기를 연결한다. LLM/AWS 운영 연결 완료를 주장하지 않는다.

이번 읽기 전용 DB 감사에서 활성 자료는 150건이다. 시설 137건 중 연결된 것은 28건(20.4%)이며, 후라노 9/24, 북토 4/10, 삿포로 15/103이다. 활성 출처 5개는 앱의 후라노·하코다테·삿포로·신치토세 4개 지역에 속한다. 다른 8개 지역에는 현재 승인·활성 관광 자료가 없으므로 기본 카탈로그 추천을 사용한다. 여행일 행사로 노출 가능한 것은 감사일 기준 0건이다. 낮은 자료 연결률과 지역 범위는 기능 가치의 한계이며 알고리즘 결함과 구분한다.

실제 운영 판단에는 배포 환경의 추천/경로 부하, 여러 인스턴스의 합계 호출량, 복원·권한·관측 경로의 검증이 남아 있다. 이번 지역 조회의 5초 로컬 검사나 기능 E2E를 운영 Valhalla 용량 검증으로 해석하지 않는다.
