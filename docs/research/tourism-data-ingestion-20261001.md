모든 출처는 `CC-BY-4.0`이며 화면에서 발행자·원문 CSV·라이선스를 확인한다. 저장된 raw blob 해시와 정제 batch 해시는 서로 다른 값이다. 출처별 실제 URL·해시·활성 snapshot ID·조회 시점은 [검증 JSON](tourism-data-ingestion-20261001.json)에 기록했다. 원본 CSV·상태 SQLite·요청 로그·개인 연락처 컬럼·브라우저 캡처는 Git에 포함하지 않았다.

동일 상태 디렉터리의 도메인 gate와 프로세스 잠금을 사용하여 9번 요청했다. 응답은 200 7회, robots 조건부 304 2회였다. 설정 간격은 60초이며 실제 로그 최솟값은 **59.999772초**였다. 0.228ms 차이를 숨기지 않고 기록했으며, 대기 후 기준 시각을 다시 검사하도록 보완했다. 모의 시각 회귀 테스트는 수정 전 실패·수정 후 통과했다. 수정 후 외부 사이트를 다시 수집해 장기 간격을 측정한 결과는 아니다.

## 연결률과 한계

활성 snapshot의 `sourceId + externalId`를 기록 단위로 삼는다. 시설 24건 모두 좌표가 있으며, 기존 장소에 연결된 8건의 비율은 **8/24 = 33.3%**다. 행사 13건은 시설 분모에서 제외한다. 같은 지역의 250m 안에서 NFKC·소문자·구두점/공백/기호 정규화 명칭이 일치하는 후보가 정확히 하나여야 연결한다. 이번 작업에서 매칭 조건·catalog·별칭을 변경하지 않았다.

| 시설 결과 | 건수 | 의미 |
|---|---:|---|
| 연결 | 8 | 보수적 자동 연결 조건 충족 |
| 명칭 불일치 | 10 | 250m 안에 후보는 있으나 정규화 명칭이 다름 |
| 주변 후보 없음 | 6 | 같은 지역 catalog의 250m 안에 후보 없음 |

명칭 불일치에는 `ふらのワインハウス`와 `富良野ワインハウス`(약 15.6m)처럼 수동 대조할 후보도 있고, 스키장과 인근 호텔처럼 다른 시설일 수 있는 후보도 있다. 가까움만으로 동일 시설이라고 판단하지 않는다. 주변 후보 없음도 폐업이나 실제 시설 부재를 뜻하지 않는다. 33.3%는 연결률이며 추천 정확도·장소 동일성 정답 검증 결과가 아니다. 전체 12지역을 검증한 결과도 아니다.

후라노 행사 10건은 명시적 시작·종료일이 없고(반복 일정 9, 날짜 불명 1), 에니와 3건은 2026-10-01 이전에 종료됐다. 따라서 이 기준일에 노출 가능한 행사는 0건이다. 행사 2건은 좌표가 있으나 시설과 달리 자동 장소 연결 대상이 아니다. 날짜 분류는 출처 문구와 날짜 기재에 따른 휴리스틱이며 개최 보장이 아니다.

37건 모두 원문 수정 시점이 없으며 시설 5건은 과거 영업시간을 포함한다. 새 수집일은 현재 영업시간이나 방문 제한의 최신성을 보장하지 않는다. 화면에서도 과거 시간과 원문 수정 시점 미제공을 표시한다.

## 실제 API·화면 검증

`tests/e2e/tourism-published.spec.ts`를 별도 활성화하여 1440×960과 390×844에서 추천·근거·날씨·경로 응답을 가짜 자료로 바꾸지 않고 실행했다. 실제 발행된 `五郎の石の家`를 유지하며 2026-11-01, WALK 조건으로 확인했다.

- 두 크기 모두 `READY`, 검색 1회, 시설 근거 2건을 인용하는 4곳 코스가 나왔다.
- 원문 CSV·CC-BY-4.0 링크와 과거 영업시간 경고를 확인했다. 시설에 잘못 표시되던 “개최 미확정” 문구를 행사에만 표시하도록 수정했다. 기존 행사 미확정 표시는 회귀 검사로 보존했다.
- 미리보기의 3구간이 모두 실제 Valhalla 결과였다. 합계 20,970m·15,002초이며 화면은 약 21.0km·250분으로 표시했다. 두 번째 화면 조회에서는 완료 캐시를 재사용할 수 있으므로 독립적인 외부 호출량 측정은 아니다.
- 예보 범위 밖 날짜이므로 날씨는 미제공으로 표시했다. 미리보기 전후 기존 일정이 그대로이고, 확정 후 서버/DB의 순서가 선택 코스와 일치하며 유지 장소가 첫 번째임을 확인했다.
- 임시 검증 계정과 해당 계정의 여행을 정리했다. 추천 품질·실제 방문 가능성·보행 안전성·운영 부하를 평가한 결과는 아니다.

## 재실행

읽기 전용 품질 도구는 승인·활성 등록부 출처의 활성 snapshot을 일관된 DB 트랜잭션으로 읽는다. DB의 권리·활성 여부도 결과와 행사 노출 집계에 반영한다. 이전 snapshot 전체를 분모로 섞지 않는다. 기준일·시설 분모·좌표 분모·미연결 사유·원문 시점 누락을 기록한다.

```bash
npm run tourism:audit -- --date 2026-10-01 --output data/processed/tourism-audit.json
TOURISM_PUBLISHED_E2E=1 npm run test:e2e -- tests/e2e/tourism-published.spec.ts
```

첫 명령의 출력 폴더는 미리 생성해야 한다. 두 번째 명령은 이번 발행 자료와 catalog, 개발 서버·Chrome·실제 외부 provider 설정이 필요하며 테스트용 계정/여행을 생성 후 정리한다. 기본 E2E에서는 실제 자료 검사 2개를 건너뛴다. CI에도 외부 HARP 수집이나 실제 자료 E2E를 연결하지 않았다.

[실행한 품질 노트북](tourism-live-data-audit-20261001.ipynb)은 정확한 profile SQL과 읽기 전용 도구 실행, 기록 수·분모·중복 ID·연결 사유 검사 및 출력 결과를 보존한다. 재실행 값은 실행 시 DB 상태에 따라 달라진다.

## 검증과 남은 작업

전체 Vitest **30개 파일·203개**, 기존 E2E **25개**(실제 자료 선택 실행 2개는 기본 실행에서 skip), 실제 자료 E2E **2개**, Python **20개**가 통과했다. build(타입 검사 포함)·lint·전체 format:check·spec:check(45 paths/28 tables)도 통과했다.

추가 CI 테스트 묶음은 첫 실행에서 기존 빈 일정 테스트의 여행 생성 응답에 `data.id`가 없어 134개 통과·1개 실패했다. 당시 HTTP 상태/본문이 기록되지 않아 원인을 확정하지 못했다. 생성 상태가 201인지 먼저 확인하는 진단을 추가한 재실행에서는 24개 파일·135개가 통과했다. 첫 실패를 해결됐다고 단정하지 않으며 후속 관찰 대상으로 남긴다.

다음 작업은 미연결 후보를 수동 대조하여 승인된 별칭/자료 보완 필요성을 판단하고, 같은 날짜 동시 요청의 외부 호출량·Valhalla 대기열을 측정하는 것이다. 자동 갱신은 운영 환경·보존/백업 정책을 정한 후 연결한다. 현재 자동 삭제·AWS 스케줄러·LLM·임베딩은 연결하지 않았다.
