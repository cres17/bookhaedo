# 관광 별칭 진단·CI 재시도·공통 승인 정책 검증 (2026-10-02)

기준 커밋: `b47f09f`, 브랜치: `ver2`. 아래는 커밋·푸시 전 로컬 검증 기록이며 원격 CI 상태는 GitHub run에서 별도로 확인한다.

## 변경

- 승인 별칭이 거절된 이유를 매칭 공통 함수에서 만들고 감사의 `aliasReview`, 발행 결과와 감사 CLI의 `aliasReviews`로 제공한다. 원문 명칭/파일 해시/지역 변경, catalog 지문 변경, 후보 부재, 모호성, 좌표 누락을 구분한다. 정확한 명칭이 유일하면 정상 연결하며, 거리 NaN은 기존 검사처럼 거절한다. 파일 해시·250m·지역·catalog 지문 보호를 완화하지 않았다.
- 별칭 파일 읽기/파싱 실패의 Promise는 캐시에서 제거하여 다음 호출이 복구할 수 있게 한다. 정확한 명칭 연결은 별칭 파일 읽기에 의존하지 않는다.
- `ops/tourism/source-policy.json`에 등록부와 별도의 승인 정책을 두고 Python 수집·정제와 TypeScript 발행이 각각 검사한다. 기존 HARP 범위와 삿포로 고정 페이지/CSV/파서/간격을 보존하며 다른 CKAN 출처는 등록부 승인만으로 허용되지 않는다. 사용자 정보, query/fragment, 인코딩 및 상대 경로 우회 반례에서 두 언어의 결과를 대조했다.
- CI 보안 검사에서 실제 high/critical 보고서는 즉시 실패한다. 알려진 429/5xx·통신 오류와 관측된 `E400 Invalid package tree`만 최대 세 번 재시도한다. 출력 해석 실패·영구 오류·반복 오류는 실패한다. 기존 high 기준 및 npm 버전은 유지한다.
