# 관광 추천 수정 및 전체 재리뷰 — 2026-10-02

기준 커밋은 `0a03440`이며 검증 대상은 현재 `ver2` 작업 트리다. 검증 시점에는 커밋·푸시·새 GitHub CI 실행을 하지 않았다. 코드 해시는 동명의 JSON에 보존했다.

## 수정과 검증

1. **수집 초기 실패가 정규화를 우회하던 문제**: robots 확인, 페이지 탐색, 중복 파일 발견 실패도 SQLite `runs`에 남긴다. 함수로 직접 실행하는 `Collector.run`도 포함한다. 기존 성공 blob과 활성 snapshot은 보존하며 정규화는 최신 실패를 거절한다. 먼저 추가한 CLI 회귀 테스트 3개는 수정 전 모두 실패했다. 최종에는 직접 호출 사례까지 4개를 검증했다.
2. **철회와 재발행 경합**: `withdrawal(source_id,external_id)`에 철회를 보존한다. 직접 SQL 갱신도 트리거가 출처 잠금을 획득하고 교체된 활성 record까지 철회한다. 새 수집은 철회 상태를 이어받고 재처리는 거절한다. 검색은 개별 flag와 지속 철회 기록을 둘 다 검사한다. 기존 자료의 flag를 지워도 근거와 행사 참고 목록에 되살아나지 않는다.
3. **운영 도구**: `npm run tourism:withdraw -- <source-id> <external-id>`는 출처를 먼저 잠근 뒤 현재 활성 자료를 찾는다. 존재하지 않는 ID는 롤백하며 출처·ID를 사용자 입력으로 SQL에 삽입하지 않는다.
4. **연결 감사**: 연결된 자료도 현재 공통 매칭 규칙으로 검사하여 조건이 어긋나면 `LINK_REVIEW_REQUIRED`와 `currentMatch`를 반환한다. 연결을 자동 변경하지 않으며 미연결 대조 자료와 구분한다. 현재 실제 자료에서는 해당 경고가 0개다.
5. **추가 검증**: 합성 삿포로 103행을 수집·정규화·발행·검색으로 연결했다. 선행 0, 원문 SHA, 출처와 라이선스, 설명·연락처·사진·요금·과거 시간 제외를 검사했다. 기존 별칭의 CSV 해시 변경 거절, DB 철회 롤백, 두 동시 실행 순서, 중복 재처리, snapshot 삭제 후 철회 보존, 업그레이드 시 기존 철회 backfill을 검사했다. 초기 전체 실행에서 기존 행사 테스트의 지속 철회 marker가 남는 것을 발견해 고유 ID와 명시적 정리를 추가했다. SQLite 테스트 연결도 확실히 닫도록 보완했다.

## 재리뷰 평가와 남은 범위

수정한 실패·경합 경로와 관광 추천의 인증/여행 접근, 30회 POST 한도, 이전 목록 보존과 조건 변경 무효화, 근거 선별·상태 판정, 경로 complete 조건을 다시 읽었다. 검증 범위에서 추가로 확인된 수정 필요 결함은 없다.

직접 SQL 철회와 snapshot 정리를 동시에 실행하면 잠금 순서 때문에 한쪽이 교착 오류로 롤백될 가능성이 있다. 운영에서는 출처를 먼저 잠그는 전용 도구를 사용한다. 철회 해제/재승인 정책은 자동화하지 않았다. 배포 환경은 새 마이그레이션을 먼저 적용해야 한다.

103행 연결 검사는 합성 fixture이며 실제 신규 수집이나 현재 영업·행사 개최 여부 검증이 아니다. 실제 발행 화면 검사는 이미 적재된 공개 자료의 흐름을 검증했다. 경로가 확인되지 않으면 불명 상태를 허용하는 기존 E2E 정책을 유지하므로 전체 외부 경로의 성공률을 뜻하지 않는다. 운영 규모 부하·추가 시설 동일성 승인·신규 지역 출처 확보는 별도 후속 작업이다.
