# Valhalla 간격·공통 연결 규칙·미연결 시설 대조 — 2026-10-01

## 구현과 검증

자체 호스팅/별도 Valhalla 주소에는 공용 서버용 전역 1.1초 대기를 적용하지 않는다. 공용 `valhalla1.openstreetmap.de`는 기본값이든 환경변수 명시값이든 간격을 유지하며, 대소문자와 도메인 끝점 표기도 같은 서버로 판단한다. 운영 모드는 공용 주소를 시작 검증과 실제 요청 전에 거절한다. 기존 신호 취소, 실패 시 직선거리/시간 미제공, 완료 캐시 정책을 보존한다. 신호가 있는 진행 중 호출을 합치는 기능은 변경하지 않았다.

`server/tourism-matching.ts`가 250m 반경, NFKC·소문자·구두점/공백/기호 정규화와 유일 후보 판단을 관리한다. 발행과 감사가 같은 함수를 호출하며, 이벤트·좌표 누락·모호한 명칭은 연결하지 않는다. 감사의 전역 같은 이름 조회는 반경 밖/지역 불일치의 설명에만 사용하고 자동 연결에 쓰지 않는다. catalog 변경 이후 일치 후보가 생겨도 감사는 `ELIGIBLE_BUT_UNLINKED`만 표시하며 기존 snapshot을 다시 연결하지 않는다.

## 동일 조건의 수정 전후 측정

현재 로컬 환경에는 자체 호스팅 Valhalla 주소가 설정되지 않았다. 실제 운영 서버 성능 대신 **30ms 지연의 loopback HTTP fixture**에서 같은 기록된 4곳의 코스, 두 동시 호출자, 호출자당 3구간, 개별 취소 신호와 비어 있는 캐시 키로 비교했다. fixture 경로 값은 합성이며 실제 도로 거리·이동시간 검증에 쓰지 않는다. 실제 HARP나 공용 Valhalla를 부하 측정용으로 호출하지 않았다.

| 측정 | 수정 전 (`1db9b30`) | 수정 후 |
|---|---:|---:|
| 외부 요청 수 | 6 | 6 |
| 전체 완료 시간 | 6074.50ms | 47.97ms |
| 마지막 요청 시작 | 5508.34ms | 5.01ms |
| 완료한 호출자 | 2/2 | 2/2 |

단일 로컬 6요청 측정이다. 전체 시간에는 네트워크 fixture와 런타임 비용이 들어간다. 전역 대기 제거를 확인한 근거이며 운영 처리량·대기열 포화·자체 호스팅 서버 용량을 입증하지 않는다. 고정 입력, 실제 요청 시작 시각, 실행 시점과 수정 코드 해시는 [검증 JSON](tourism-langgraph-review-5-20261001.json)에 보존했다.

## 재실행과 테스트

```bash
mkdir -p data/processed
npm run tourism:compare -- --source furano-places --date 2026-10-01 --output data/processed/facility-comparison.json --markdown data/processed/facility-comparison.md
npm run tourism:benchmark-routing -- --fixture --label after --output data/processed/routing-benchmark.json
```

대조 도구는 읽기 전용 감사 트랜잭션을 사용한다. unknown source 거절, 연결 완료 시설 제외, 후보를 임의로 자르지 않는 출력, 명칭/HTML 문자 escape, 입력에 승인 표시가 있어도 승인 대기로 출력하는 정책을 검사한다. 실제 DB 테스트는 새로 만든 테스트 snapshot만 사용하며, 발행/감사의 유일 명칭 일치와 모호한 후보 거절, 감사/대조 후 재연결이 일어나지 않음을 확인한다.

자체 호스팅 동시 호출 회귀 테스트는 수정 전 500ms 안 요청 1개(기대 3개)로 실패했고 수정 후 통과했다. 공용 간격, 명시된 공용 주소, 대기 중 취소와 뒤 요청 진행, 완료 캐시 재사용, 운영 공용 주소 거절을 검사했다. 새 검사 파일은 `test:ci` 묶음에도 포함했다.

전체 Vitest **33개 파일·221개**, 실제 발행 자료 2개를 포함한 전체 Playwright **27개**, Python **20개**, build(타입 검사 포함)·lint·format:check·spec:check(45 paths/28 tables)가 통과했다. 기존 Python 검사 중 SQLite 연결 ResourceWarning이 1회 있었으나 검사 실패는 없었다. [실행한 대조 노트북](tourism-facility-comparison-20261001.ipynb)은 공통 SQL, 원문 ID 중복·후보 거리/지역·승인 대기·근거 해시 연결 검사를 보존한다.

추가 `test:ci` 묶음도 27개 파일·153개가 통과했다.

실제 데이터는 장소 20,810곳·관광 자료 37건·snapshot 3개를 보존한다. 승인 별칭 발행 적용, 운영 서버 부하 측정, 자동 갱신/삭제, 신규 지역 출처와 날짜 불명 행사 화면은 이번 범위에 포함하지 않았다.
