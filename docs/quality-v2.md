GitHub에서의 자동 검사 실행 결과는 [Actions](https://github.com/cres17/bookhaedo/actions/workflows/ci.yml)를 확인합니다. 위의 로컬 통과 결과와 원격 CI 실행 결과를 구분합니다. CI는 별도 PostGIS에 빈 스키마를 만들고 키 없는 검사 모음을 실행하며, 유료/외부 제공자가 필요한 E2E는 포함하지 않습니다.

리뷰 후보 10곳 확대 시에는 상한·분류 혼합·단일 분류·후보 부족을 회귀 검사하고 README 기술 배지 13개의 SVG 응답을 확인했습니다. 전체 브라우저 E2E 결과는 기존 v2 검증 기록이며, 이번 README·리뷰 상한 변경에서 새로 실행한 결과와 구분합니다.

## 실제 연결과 모의 검사 구분

- `google-live.spec.ts`: 실제 지도 로딩, REST 연결, 경로·날씨 표시를 확인합니다.
- `places-live.spec.ts`: 실제 Google Places의 한국어 상세·사진·리뷰·출처를 확인합니다.
- 가입 → 여행 생성 → 장소 담기 → 날짜 변경 → 새로고침 복원은 실제 REST와 로컬 DB를 사용합니다.
- 악천후·맑음·예보 없음·외부 실패·느린 응답·동시 편집은 통제된 응답 또는 동시 DB 요청으로 재현합니다. 해당 날 실제 악천후였다는 주장은 하지 않습니다.
- 자동 검증용 임시 계정/장소만 생성·정리합니다. 기존 사용자 여행이나 원본 카탈로그를 초기화하지 않습니다.

## 아직 보장하지 않는 것

1. 일본어 리뷰 원문은 작성자의 국적·거주지 증거가 아닙니다. 전체 평점은 일본어 리뷰만의 평균이 아닙니다.
2. Google 표본은 전체 리뷰가 아니며, 최대 10개 사전 후보 검사로 지역 내 모든 좋은 장소를 순위화하지 않습니다. 후보 부족·시간 초과·품질 기준 미달이면 결과가 10개보다 적을 수 있습니다.
3. 실내 태그·직선거리·예보는 현장 영업/휴무/안전/완전한 최적 동선을 보장하지 않습니다.
4. 장소 기본 데이터의 신선도와 실제 외부 제공자 상태는 운영 중 계속 확인해야 합니다.
5. 다중 인스턴스 요청 제한, 중앙 모니터링, 관리자 MFA/SSO, 대규모 부하 시험과 백업 복구 훈련은 [운영 안내](operations.md)의 후속 과제입니다.

현재 문서의 기준은 README → OpenAPI/DBML → 이 검증 기록입니다. 이전 날짜의 평가 문서는 당시의 스냅샷으로 남깁니다.
