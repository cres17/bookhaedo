# 로컬 배포용 화면 빌드: 개선 전후 브라우저 비교

측정일: 2026-09-22. 개선 전후 각각 3회, 실행 순서를 `전→후 / 후→전 / 전→후`로 바꿨다.

## 개선 전 값의 출처

**성능 개선 전에 로그인·DB·화면 표시 전체를 측정해 둔 기록은 없다.** 기존 문서의 48.64% 경로 단축은 외부 API 호출 구간 측정으로, 화면 전체 개선율이 아니다.

이번 비교는 현재 코드의 별도 복사본 두 개를 만들고, 비교용 복사본에서 성능 변경만 되돌린 **재구성 기준 버전의 재측정**이다. 실제 과거 운영 배포나 당시 측정값을 복원했다는 뜻은 아니다.

- `frontend/src/store.ts`, `server/providers.ts`, `server/routing.ts`, `server/place-details.ts`: 커밋 `71bca6fd326d78c5fd4c3037fcd63fcb96a2c653`의 원본 파일로 복원.
- `server/routes/providers.ts`, `server/day-alternatives.ts`: 개선 전 미커밋 파일이므로 과거 커밋에 없다. 작업 기록에서 확인한 순차 호출 동작을 비교용 복사본에서 재현했다. 현재 병렬 매핑 대신 순차 매핑을 호출하며, 인증·권한·DB 조회·응답 조립은 그대로 유지했다.
- 나머지 화면, 로그인/세션 구현, DB 스키마와 카탈로그는 동일하다. 측정 과정에서 실제 작업 폴더의 서비스 코드는 되돌리지 않았다.
- 비교 대상 파일들의 변경 전후 SHA-256과 복원 방식을 원본 결과에 기록했다.

## 환경과 측정 경계

두 버전 모두 Vite **production build**를 생성하고 Express가 정적 파일을 제공했다. Vite 개발 서버는 사용하지 않았다. 로컬 PostgreSQL의 실제 카탈로그를 읽고, 측정 전용 계정·여행·날짜·4개 장소를 양쪽에서 동일하게 사용했다.

백엔드는 `NODE_ENV=test`로 실행했다. 로컬 HTTP, 공개 Valhalla 개발용 서버 사용, 프로세스별 요청 제한 구분을 위한 설정이다. 인증·암호 검증·세션·여행 권한·DB 읽기/쓰기는 실제 앱 구현이다. **운영용 HTTPS·CSP·Secure 쿠키·자체 Valhalla 운영 환경과 동일한 설정을 측정한 것은 아니다.** 운영 가드를 약화하거나 실제 서비스를 배포하지 않았다.

- 브라우저: 로컬 Chrome headless, 1440×960. 버전은 원본 결과에 기록.
- 매 회차: 새 서버 프로세스와 새 브라우저 컨텍스트. 앱 캐시는 비어 있는 상태에서 시작.
- 같은 회차 내 재조회는 앱 캐시와 브라우저 HTTP 캐시를 활용한다. 재조회 뒤 순서 변경은 `A→B→C→D`에서 `B→A→C→D`로 변경한다.
- 첫 일정/재조회/순서 변경 완료: 실제 Valhalla 경로 3개, Open-Meteo 날씨, Google 지도 타일 초기 로딩 완료, 화면 전환 종료, 폰트 준비 및 두 번의 animation frame을 확인.
- 첫 기본 일정: 장소 목록 4개를 DOM에서 확인하고 폰트와 두 번의 animation frame을 기다림. 외부 경로·날씨 완료 전 표시되는 기본 데이터 구간이다.
- 로그인 응답: 브라우저의 실제 로그인 요청 시작부터 응답 완료까지.
- 첫 일정 표시: 로그인 요청 시작부터 화면 준비 조건 확인까지.
- 로그인 화면/재조회: 브라우저 navigationStart부터 준비 조건 확인까지.
- 순서 변경: 실제 저장 PUT 요청 시작부터 갱신 화면 준비 조건 확인까지.

자동 클릭 도구의 버튼 안정화 대기시간을 시작점에서 제외했다. 다만 자동 검증의 상태 확인 간격 때문에 사용자가 보는 첫 픽셀의 정확한 시점보다 늦게 측정될 수 있다. API 요청 시간도 별도 기록했다. 화면 측정은 LCP나 INP 표준 지표가 아니다.

## 최종 결과

각 버전 3회 중앙값. 단축률은 `(1 - 개선 후 중앙값 / 개선 전 중앙값) × 100`이다.

| 측정 구간 | 개선 전 | 개선 후 | 단축률 | 해석 |
| --- | ---: | ---: | ---: | --- |
| 로그인 화면 준비 | 753.30ms | 714.00ms | 5.22% | 실행 범위가 겹쳐 개선 단정 어려움 |
| 실제 로그인 HTTP 응답 | 63.11ms | 65.94ms | -4.48% | 약 2.83ms 증가, 개선 확인 못함 |
| 로그인 후 기본 일정 표시 | 881.81ms | 881.17ms | 0.07% | 사실상 동일 |
| 로그인 후 첫 일정·지도·날씨·경로 표시 | 2,966.81ms | 2,963.94ms | 0.10% | 사실상 동일 |
| 같은 일정 새로고침 후 전체 표시 | 3,295.20ms | 896.30ms | **72.80%** | 반복 조회에서 일관된 개선 |
| 순서 변경 저장 후 전체 표시 | 3,264.59ms | 1,466.90ms | **55.07%** | 변경 없는 경로 재사용 효과 |

실행 간 최솟값–최댓값:

| 구간 | 개선 전 범위 | 개선 후 범위 |
| --- | ---: | ---: |
| 로그인 화면 | 751.30–944.60ms | 669.40–775.60ms |
| 로그인 HTTP | 50.82–70.86ms | 65.49–68.93ms |
| 기본 일정 | 863.82–892.39ms | 879.34–884.66ms |
| 첫 전체 일정 | 2,965.82–3,007.79ms | 2,948.37–2,979.86ms |
| 재조회 | 3,247.30–3,295.30ms | 880.00–897.40ms |
| 변경 후 표시 | 3,263.74–3,296.37ms | 1,464.06–1,515.49ms |

회차당 서버 외부 호출은 경로 **9→5회**, 날씨 **3→2회**였다. 순서 변경으로 첫 장소가 달라져 날씨 좌표도 바뀌므로 날씨를 한 번 새로 요청하는 것이 정상이다. Google 지도 스크립트·타일 등 브라우저 외부 요청은 이 서버 호출 수에 포함하지 않는다.

6회 모두 실제 로그인이 성공했고, 순서 변경이 DB에 저장된 것을 별도 조회로 확인했다. 브라우저 실행 오류와 지도 대체 화면, 직선거리 경로는 성공 측정으로 인정하지 않았다. 측정 전용 계정·여행은 종료 후 삭제했고 임시 서버를 종료했다.

## 해석과 한계

이번 개선의 확인된 효과는 **첫 진입 가속보다 반복 조회와 일정 편집 대기 감소**다. 로그인과 첫 화면이 크게 빨라졌다고 주장할 수 없다. 운영 환경이나 모든 페이지에 동일한 비율이 적용된다고도 말할 수 없다.

버전당 3회인 소규모 로컬 비교다. DB·OS·DNS·외부 제공자 캐시는 강제로 비우지 않았으며 네트워크/지도 타일 변동은 남아 있다. 운영 인그레스, 다중 인스턴스, 동시 사용자, 모바일 및 느린 네트워크는 측정하지 않았다. 운영 p95·SLA 결과가 아니다.

최초 예비 측정에서는 자동 클릭 안정화 대기시간이 포함되어 로그인 수치 해석이 부정확할 수 있었다. 예비 결과는 `pilot-report.json`으로 보존하고, 위 표는 실제 브라우저 요청 시각 기준으로 다시 측정한 `report.json`만 사용했다. 앱 코드는 예비 측정과 최종 측정 사이에 변경하지 않았다.

## 재현과 원본

`npm run benchmark:browser -- --live --baseline 71bca6f --rounds 3`

로컬 DB와 Chrome, 기존 외부 API 설정이 필요하다. 로컬 DB만 허용하고 실제 외부 API를 사용하므로 제공자 과금이 발생할 수 있다. 실행은 측정용 계정을 만들어 일정 순서를 변경한 후 정리한다. `.env`나 세션 토큰, 비밀번호는 결과에 기록하지 않는다.

- [측정 스크립트](../scripts/benchmark-browser.ts)
- 최종 원본 결과: `output/browser-benchmark/report.json`
- 계정·임시 서버 정리 확인: `output/browser-benchmark/cleanup.json`
- 전후 화면: `output/browser-benchmark/before-planner.png`, `after-planner.png`

`output/`은 Git 제외 경로다. 위 실행 결과와 화면은 로컬 보관 자료이며 이 저장소에는 포함하지 않는다. 공개 측정표의 범위와 한계는 위 설명을 따른다.
