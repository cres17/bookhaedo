## 자동 테스트와 실제 호출의 구분

- `tests/weather-alternatives.test.ts`: 실제 Express·PostgreSQL·장소 원본 사용. 예보/경로 제공자만 통제해 각 날씨와 실패 분기를 재현했다. 후보 없음 테스트는 후보 SELECT 응답만 빈 결과로 대체한다.
- `tests/e2e/weather-alternatives.spec.ts`: 실제 계정·여행 생성 및 PATCH 저장·재조회. 예보·추천 GET 응답은 고정하고 지도 스크립트는 차단하여 Google 장애 시에도 UI 흐름을 검증했다. 한 번의 PATCH는 충돌 응답으로 통제해 실패 시 보존을 확인한다.
- 기존 `google-live.spec.ts`, `places-live.spec.ts`는 별도로 실제 Google 연결을 검증한다.
- 각 테스트가 생성한 고유 이메일 계정과 해당 여행만 삭제했다. 기존 사용자나 장소 원본은 삭제하지 않았다.

## 실제 예보·후보·경로 연동 사례

삿포로 2026-09-09 예보를 조회한 시점의 결과:

- Open-Meteo: 이슬비, 최고 20.6°C / 최저 14.4°C, 강수확률 100%, 일 최고 풍속 22.2km/h.
- 신규 추천 GET: HTTP 200, READY, 실제 PostGIS 실내 분류 후보 3곳 반환. 단일 호출 관측 1,729ms(성능 목표나 평균이 아님).
- 후보: ギャラリー大通美術館(직선 610m), 宮部金吾記念館(1,134m), 北大植物園温室(1,063m). 장소 분류 기준이며 당일 개방을 확정한 목록이 아니다.
- 선택 후보 미리보기: HTTP 200. 기존 인접 구간 1,346m / 188초, 변경 구간 995m / 138초. 두 결과 모두 Valhalla 응답으로 확인했다.
- 위 사례는 전체 여정이 아니라 변경 대상 앞뒤 인접 구간의 비교다. 실시간 교통·적설·휴업을 반영한 안전 경로가 아니다.

## 제한 사항과 후속 과제

1. 공식 기상특보가 아닌 자체 탐색 기준이다. 일 단위 예보이며 시간대별 방문 날씨는 판단하지 않는다.
2. 후보는 직선 동선으로 정렬하고 선택 후에만 실제 경로를 비교한다. 섬·산악·해협 때문에 실제 우회가 클 수 있다.
3. 실내 분류가 시설 전체의 실내 여부나 당일 개방을 보장하지 않는다. 원문 운영시간의 복잡한 규칙·계절별 운영기간·임시 휴업은 자동 판정하지 않는다.
4. 예보는 오늘부터 10일 이내다. 후보가 없으면 임의 장소·시간을 생성하지 않는다.
5. 자동 일정 변경, 하루 전체 재설계, 확정 후 자동 되돌리기는 범위 밖이다. 사용자 확정 전 취소만 지원한다.
6. 교체 대상의 예약 메모를 다른 장소로 옮기면 잘못된 정보가 될 수 있어 비운다. 확정 화면에서 이를 안내한다.
7. 다중 사용자 부하·장시간 안정성·추천 만족도는 이번 기능 테스트로 검증하지 않았다.

풍속 단위와 제공 항목 참고: [Open-Meteo 공식 문서](https://open-meteo.com/en/docs).
