# Book해도 품질 검사 계약

현재 GitHub quality 워크플로는 정적 검사·명세 생성본 일치·DB 테스트·Python·빌드와 관광 E2E를 실행한다. 전체 로컬 Vitest와 CI 목록은 같은 범위가 아니며 catalog 의존 6개 파일은 CI 목록 밖이다.

Drift Gate는 코드 변경과 지정 문서·검증 파일의 동반 변경을 검사한다. 기능 정확성·모든 오류 응답의 의미 일치·운영 용량을 증명하지 않는다. `.drift-gate.yml`의 stable 문서 경로를 사용하고 사후 연구 보고서 파일을 매번 수정하도록 요구하지 않는다. optional LLM 없이 고정한 Drift Gate 01e28e1620941a539d3e9c14972201b30adafd3b 소스를 사용한다.

```sh
npm run check:drift -- --base <검토한-기준-커밋> --tool <Drift-Gate-저장소> --python <의존성이-설치된-Python>
```

로컬 변경에 새 파일을 포함하려면 먼저 Git에 추가한다. 결과는 기본 `.drift-gate-report/` 또는 `--out` 경로에 저장한다. 이 경로는 Git에서 제외한다. wrapper는 정책 없음·빈 규칙·잘못된 도구 버전·실행 실패·오래된 결과 재사용을 통과로 처리하지 않는다. 문서/테스트만 변경하거나 변경이 없거나 어느 규칙에도 해당하지 않는 경우에는 검사 범위를 출력한다. 도구 버전 갱신은 판정 변화 검증 후 PIN을 변경한다.

현재 이 wrapper는 로컬 사전 검증이다. Drift Gate GitHub CI job은 아직 추가하지 않았다. CI 연결 시에는 신뢰할 수 있는 기준 정책과 PR 정책 변경을 구별하고 고정 도구 버전을 설치해야 한다. 현재 PR이 정책을 삭제하거나 약화해 검사 자체를 우회하지 않는지도 검증한다.

필수 대조군은 정책 제거 시 실패, OpenAPI 또는 복구 E2E의 동반 변경을 되돌렸을 때 실패, 실제 변경의 통과다. 동작 반례는 DB·API·브라우저 검사로 별도 확인한다. 문서 동반 변경을 유지하고 운영 코드만 되돌린 입력이 Drift Gate를 통과할 수 있다는 기존 검증 결과도 보존한다.
