01 · Product Intent

기획 의도와 해결하려는 불편

유명 도시 중심의 여행 검색에서 벗어나, 소도시의 현지 장소를 발견하고 날씨 변화에도 여행을 이어가도록 돕습니다.

PAIN 01

소도시 장소 탐색의 공백

기존 플래너에서 홋카이도 소도시와 비주류 장소가 충분히 노출되지 않아 별도 검색을 반복해야 합니다.

PAIN 02

일본어 장소명의 장벽

한국어 정보가 부족한 장소는 검색과 비교가 어렵습니다. 한국어 상세정보와 일본어 원문을 함께 제공합니다.

PAIN 03

급변하는 날씨와 일정 중단

눈·비로 계획을 실행하기 어려워졌을 때 날씨에 맞는 실내·도심 후보를 다시 찾는 인지 부담이 큽니다.

PAIN 04

유명 장소에 편중된 동선

여행 후에야 알게 되는 장소를 줄이도록 현지 데이터와 일본어 리뷰 단서를 탐색 과정에 연결합니다.

핵심 경험 — 지역과 가고 싶은 장소를 검색 → 지도에서 비교 → 날짜별 일정에 추가 → 거리·시간·날씨를 확인 → 순서를 조정합니다.

검색 요청

place-search.ts가 지역명과 업종·활동 동의어를 분리하고, PostGIS JSONB 태그 조건과 잔여 장소명을 함께 적용합니다.

장소 상세

로컬 장소의 일본어 이름과 좌표로 Google 후보를 조회하고, 이름·거리 검증을 통과한 경우에만 상세정보를 연결합니다.

일정 저장

세션 사용자 소유권을 검사한 뒤 날짜, 장소, 순서를 트랜잭션으로 저장하고 순서 변경 후 경로를 재계산합니다.

오류 응답

검증 실패 400, 인증 실패 401, 권한 부족 403, 미존재 404, 외부 연동 실패는 안전한 대체 응답으로 구분합니다.

10 · Integration & Security

외부 API 경계와 보안 원칙

GOOGLE MAPS

브라우저 지도 표현

Maps JavaScript API는 허용 웹사이트 제한이 적용된 브라우저 키로 지도·마커·경로선을 표시합니다.

GOOGLE PLACES

검증된 상세정보

서버가 장소명·거리 일치를 확인한 후 한국어 상세를 반환합니다. 존재하지 않는 공식 사이트를 생성하지 않습니다.

ROUTES · VALHALLA

경로 계산과 대체

Google Routes를 우선 사용하고 지원 범위·실패 조건에 따라 Valhalla 기반 경로로 보완합니다.

OPEN-METEO

날씨 예보

서버에서 기온·강수·적설을 받아 추천과 일정 화면에 전달하며, 미확인 상태를 실제 정보처럼 표현하지 않습니다.

  • DB와 서버용 API 키는 브라우저에 직접 노출하지 않음
  • 세션 쿠키 HttpOnly·SameSite 적용, 운영 HTTPS에서는 Secure 적용
  • Zod 입력 검증, Helmet 보안 헤더, 인증·상세 API 요청 제한
  • 관리자 라우트 RBAC와 변경 감사 로그
  • 사진·리뷰 응답을 서비스 DB에 영구 복제하지 않음
